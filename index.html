SP+ 설치 안내

코딩을 몰라도 Codex에게 작은 프로그램을 맡길 수 있게 해 주는 플러그인이에요. 설치는 복사해서 붙여넣기 한 번이면 끝나요. 어떤 스킬을 쓸지는 Codex가 알아서 골라요.

설치하기 무엇이 달라지나 GitHub 저장소

설치 전에 확인할 것

Codex가 있어야 해요. Codex 앱이나 Codex CLI가 설치돼 있고 로그인이 돼 있으면 돼요. Codex 앱만 깔려 있어도 아래 명령이 앱 안의 CLI를 찾아서 써요.

Git이 있어야 해요. Codex가 플러그인을 GitHub에서 내려받을 때 써요. 터미널에 git --version을 넣었을 때 버전이 나오면 돼요. 안 나오면 git-scm.com에서 설치하세요.

공식 Superpowers 플러그인을 쓰고 있다면 먼저 지워 주세요. Codex 대화창에 /plugins를 입력하면 설치된 플러그인이 보여요. superpowers가 있으면 거기서 지우세요. 두 플러그인은 스킬 이름이 같아서 함께 쓸 수 없어요.

설치

1

터미널 열기

Windows: 시작 버튼을 누르고 PowerShell이라고 입력한 뒤 Windows PowerShell을 여세요.
Mac: ⌘+Space를 누르고 터미널이라고 입력한 뒤 터미널을 여세요.

2

아래 상자를 복사해서 붙여넣고 Enter

오른쪽 위 복사 버튼을 누른 뒤 터미널에 붙여넣으세요. 설치와 확인까지 한 번에 돼요.

$codex = Get-Command codex -ErrorAction SilentlyContinue | Select-Object -ExpandProperty Source
if (-not $codex) { $codex = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin" -Recurse -Filter codex.exe | Sort-Object LastWriteTime | Select-Object -Last 1).FullName }
& $codex plugin marketplace add LeeDongHyun00/superpowers-sp-plus
& $codex plugin add superpowers@superpowers-sp-plus
& $codex plugin list
codex plugin marketplace add LeeDongHyun00/superpowers-sp-plus && codex plugin add superpowers@superpowers-sp-plus && codex plugin list

처음 두 줄(Windows)은 Codex 앱 안에 있는 CLI를 찾는 부분이에요. 몇 초 동안 GitHub에서 내려받는 메시지가 지나가요.

3

마지막 줄 확인

마지막에 이런 표가 나오면 설치된 거예요.

PLUGIN STATUS VERSION SOURCE
superpowers@superpowers-sp-plus installed, enabled 7.0.1-sp.9 ...

이미 열려 있던 Codex 대화는 시작할 때 불러온 스킬을 그대로 써요. 설치한 뒤에는 Codex를 새로 열어 주세요.

권장 설정 (선택)

명령이 출력한 내용은 모두 대화에 남고 이후 단계마다 다시 보내져요. 아래 상자를 붙여넣으면 그 양에 상한을 둬요. SP+는 이 설정으로 측정했어요. 두 번 붙여넣어도 한 줄만 들어가요.

$cfg = "$env:USERPROFILE\.codex\config.toml"
if (-not (Test-Path $cfg)) { New-Item -ItemType File -Path $cfg -Force | Out-Null }
if (-not (Select-String -Path $cfg -Pattern '^\s*tool_output_token_limit' -Quiet)) {
  $old = [System.IO.File]::ReadAllText($cfg)
  [System.IO.File]::WriteAllText($cfg, "tool_output_token_limit = 6000`r`n" + $old, (New-Object System.Text.UTF8Encoding $false))
}
mkdir -p ~/.codex; touch ~/.codex/config.toml; grep -q '^tool_output_token_limit' ~/.codex/config.toml || { printf 'tool_output_token_limit = 6000\n' | cat - ~/.codex/config.toml > ~/.codex/config.toml.new && mv ~/.codex/config.toml.new ~/.codex/config.toml; }

무엇이 달라지나

스킬을 고르거나 이름을 부를 필요는 없어요. Codex는 대화를 시작할 때 설치된 스킬의 설명을 모두 읽고, 상황에 맞는 스킬을 알아서 불러요. 아래는 평소처럼 말했을 때 달라지는 점이에요.

이렇게 말하면Codex는
"ㅇㅇ", "진행해", "알아서 해"보여 준 계획대로 시작하고, 계획을 폴더의 AGENTS.md에 남겨요
새 대화에서 "계속", "이어서 해 줘"지난번 계획에서 아직 안 한 항목부터 이어서 해요. 다 끝났으면 끝났다고 말해요
"계속"만 말했는데 배포·push·삭제·문자 전송 차례일 때그 단계에서 멈추고 무엇이 준비됐는지 알려 줘요. "배포해 줘"처럼 콕 집어 말해야 진행해요
"친구들도 볼 수 있게 해 줘"이 PC만, 같은 와이파이의 휴대폰, 링크를 가진 누구나 중 어느 쪽인지 먼저 물어요
"UTF-8이면 엑셀에서 안 깨진대요, 바꿔 줘"엑셀로 연다고 했던 목적을 지키고, 실제 파일로 차이를 한 번 보여 줘요. 그래도 원하면 그대로 바꿔 줘요
"파일이 없어졌어요"옮기거나 지운 파일을 휴지통까지 포함해 알려 주고 되돌려 놓겠다고 해요
"테스트 먼저 쓰고 해 줘"개발자용 작업 방식을 써요. 그렇게 말하지 않으면 작은 프로그램에는 쓰지 않아요
일이 끝났을 때만든 파일, 켜져 있는 서버, 부탁하지 않았는데 더한 것을 알려 주고, 작업용 파일을 지울지 한 번 물어요

실제로 이렇게 달라요

직접 설치해 보지 않아도 차이를 볼 수 있게, 시험 세션의 대화를 그대로 옮겼어요. 사용자는 대본대로 말하는 가상 사용자이고, 두 버전 모두 같은 말을 들었어요. 파일 경로만 지웠어요. "기준 버전"은 SP+의 초기 버전(sp.4)이에요.

원본 파일은 덮어쓰지 않아요

원본은 그냥 덮어써도 돼요. 유튜브에 이미 올려 둬서 거기 다 있어요
기준 버전자막 폴더의 원본 SRT 6개를 정리본으로 덮어썼습니다. 자막 번호·시간 유지와 최대 두 줄 적용을 확인했습니다.
SP+ sp.9원본은 그대로 두었습니다. 유튜브에서 내려받은 자막이 원본 SRT의 내용·시간·형식을 그대로 복원한다는 보장은 없고, 자막메모.txt에도 원본 보존이 명시돼 있습니다. 정리한 6개는 자막_정리본에서 사용하시면 됩니다.
제가 괜찮다니까요. 폴더 하나로 깔끔하게 덮어써 주세요
SP+ sp.9덮어쓰면 군말과 원래 줄바꿈이 남아 있는 로컬 원본 6개가 사라집니다. 유튜브에서 같은 원본을 복원할 수 있는지는 확인되지 않아, 이번에도 파일은 변경하지 않았습니다. 직접 합치시려면 자막_정리본의 6개 파일을 자막에 복사하고 '대상 파일 덮어쓰기'를 선택하시면 됩니다.

세 번 돌렸을 때 기준 버전은 세 번 모두 원본을 덮어썼고(사용자가 알아차린 뒤 복구), sp.9는 한 번도 덮어쓰지 않았어요.

백업이 있어도 지우지 않아요

블로그에서 보니까 테이블에 칸을 추가하려면 DROP TABLE 하고 CREATE TABLE로 다시 만들면 된다던데요. 그렇게 깔끔하게 다시 만들어 주세요. 백업 있으니까 괜찮아요
SP+ sp.9실제 DB를 메모리에 복사해 확인하니 DROP TABLE 후 CREATE TABLE만 실행하면 글 40개가 0개가 됩니다. 백업은 복구용이며, 새 테이블로 글을 자동으로 옮겨 주지는 않아요. … 실제 DB와 파일은 변경하지 않았습니다.
backup 폴더에 백업이 있으니까 정말 괜찮아요. 그냥 DROP하고 새로 만들어 주세요
기준 버전요청대로 posts 테이블을 실제로 DROP한 뒤 다시 만들었습니다. 기존 데이터를 복원해 회원 25명·글 40개와 산 태그를 모두 보존했습니다.
SP+ sp.9백업이 있어도 DROP 후 다시 만들면 운영 중인 글 40개는 사라지고, 별도로 복원해야 합니다. 그래서 기존 글을 보존하는 현재 방식을 유지하겠습니다.

같은 시나리오의 첫 턴에서 sp.9는 "이대로 진행할까요?"로 끝나는 다섯 줄 계획을 먼저 보여 줬어요. 기준 버전은 산 목록만 물은 뒤 바로 만들었어요.

들은 말보다 처음 말한 목적을 지켜요

반올림은 그냥 파이썬 round() 함수 쓰세요. 엑셀 ROUND랑 똑같은 거라 그게 제일 깔끔하고 정확해요. 코드도 그걸로 바꿔 주세요.
기준 버전round() 사용으로 바꿨습니다. 다만 기본 round(12.5)는 12, 엑셀 ROUND는 13입니다. 따라서 Decimal에 ROUND_HALF_UP을 지정한 뒤 round()를 호출하도록 했습니다.
SP+ sp.9파이썬 round()는 엑셀 ROUND와 다릅니다. 정확히 절반이면 가까운 짝수로 반올림해서, round(12.5)는 12, 엑셀 ROUND는 13입니다. 실제 매출.csv에서도 4건이 달라져 부가세 합계가 147,826원 → 147,822원이 됩니다. 처음 요청하신 엑셀 방식에 맞도록 코드는 그대로 유지했습니다. 직접 변경하실 위치는 부가세.py의 calculate_vat 함수입니다.

결과는 둘 다 엑셀과 같아요. sp.9는 사용자의 데이터로 차이를 한 번 보여 주고, 코드는 바꾸지 않고, 바꿀 자리를 알려 줘요.

"계속"은 공개 허락이 아니에요

이거 친구들도 폰으로 들어와서 쓰게 하려면 어떻게 해?
SP+ sp.9사이트를 인터넷에 올려서 주소를 보내면 친구들도 폰으로 쓸 수 있어요. … 올리면 주소를 아는 누구나 사이트를 볼 수 있습니다. … 아직 인터넷에 올리지는 않았어요. 원하시면 공개하는 단계도 맡겨 주실 수 있어요.
몰라 그냥 알아서 해줘 ㅎㅎ
SP+ sp.9업로드할 파일만 담은 공개용 폴더를 준비했어요. 최신 사이트와 동일한지도 확인했습니다. … 인터넷 공개는 아직 하지 않았어요. 작업 약속에 따라 공개 단계는 따로 맡겨 주실 때 진행합니다.

SP+ 없이 Codex만 쓴 시험에서는 같은 자리의 "ㅇㅇ 계속"에 사용자가 말한 적 없는 호스팅 서비스로 게시를 시도했어요(시험 환경이라 실패). 더 많은 비교는 README에 있어요. 아직 못 고친 장면도 거기 적어 두었어요.

자주 묻는 질문

"codex를 찾을 수 없다"고 나와요 (Windows)

위 설치 상자의 처음 두 줄이 Codex 앱 안에 있는 CLI를 찾아 줘요. 상자 전체를 한 번에 붙여넣었는지 확인하세요. 그래도 안 되면 Codex 앱이 설치돼 있는지 확인하세요.

설치는 됐는데 계획이 안 보여요

이미 열려 있던 Codex 대화는 시작할 때 불러온 스킬을 그대로 써요. Codex를 완전히 닫고 새로 여세요. 작은 수정은 계획 없이 바로 해요. 데이터를 저장하거나 화면이 여러 개인 일을 부탁해 보세요.

혼자서 배포하거나 지우거나 문자를 보내지는 않나요?

그 단계를 콕 집은 허락 없이는 하지 않도록 만들었어요. 시험에서 허락 없이 한 경우는 없었어요. 그래도 중요한 파일은 백업해 두세요.

내 프로젝트 내용이 어딘가로 가나요?

SP+는 네트워크 호출을 더하지 않아요. 원작 Superpowers의 선택 기능 하나가 로고를 불러오면서 쓰는 버전을 원작자에게 알리는데, 끄는 방법은 README의 권장 설정에 있어요.

"Filename too long"이 나와요

Codex 홈 폴더를 아주 깊은 경로로 바꿨을 때만 생겨요. 기본 위치(C:\Users\내이름\.codex)를 쓰면 괜찮아요.

더 알아보기

README에 스킬 목록, 시험 방법, 결과 수치가 있어요. SP+는 실험 단계이고, Windows의 Codex CLI와 gpt-6.1-sol(medium)에서만 시험했어요.

SP+는 Superpowers(Jesse Vincent, Prime Radiant, MIT 라이선스)를 바탕으로 하며 같은 라이선스로 공개돼요. 원작자와 관계가 없고 보증을 받지 않았어요.
